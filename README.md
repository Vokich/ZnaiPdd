# Знай ПДД

Сайт использует React и TypeScript, серверную часть Django и REST API по адресу `/api/`. Веб-клиент, API и Django Admin работают на одном домене.

## Локальный стенд

Запустите Docker Desktop и выполните из корня проекта.

```sh
docker compose -p znaipdd-dev --profile dev up --build -d
```

Сайт доступен на [localhost:5173](http://localhost:5173/), проверка API — на [localhost:5173/api/health/](http://localhost:5173/api/health/). Профиль `dev` запускает PostgreSQL и хранит базу и медиа в собственных томах Docker. При прямом запуске Django без `POSTGRES_HOST` используется отдельный локальный файл `db.local.sqlite3`. Знаки и организации можно добавить через [Django Admin](http://localhost:5173/admin/).

```sh
docker compose -p znaipdd-dev --profile dev exec api-dev python manage.py test
```

Для разработки с автоматической синхронизацией файлов используйте `docker compose -p znaipdd-dev --profile dev up --build --watch`.

## Первый администратор

Укажите `DJANGO_SUPERUSER_USERNAME` и `DJANGO_SUPERUSER_PASSWORD` в локальном `.env`. Оба профиля Docker создают активного суперпользователя Django после миграций, перед запуском сервера. При повторном запуске пароль существующего суперпользователя сохраняется. Если логин уже занят другой учётной записью, задайте свободный логин. Когда обе переменные пусты, создание пропускается.

## Профиль prod

Скопируйте `.env.example` в `.env` при первичной настройке. Укажите `DJANGO_SECRET_KEY`, `POSTGRES_PASSWORD`, домен в ASCII или Punycode и существующий каталог медиа. Django работает с UID и GID `10001` и использует этот каталог для загрузок. PostgreSQL доступен Django внутри сети Docker, его данные находятся в томе `postgres_data`. Домен должен указывать на сервер, а порты 80 и 443 должны быть доступны для Caddy.

```sh
docker compose --profile prod up --build -d
```

Django применяет миграции при старте. Caddy отдаёт сборку React, обслуживает TLS и направляет запросы `/api/` и `/admin/` в Django. Существующие тома Caddy сохраняют сертификаты при обновлении контейнеров.

### Доступ к отчётам и справочник организаций

В разделе «Пользователи» выберите профиль доступа: «Пользователь», «Педагог» или «Администратор». Назначайте «Педагог» после проверки учётной записи. Этот профиль открывает собственные отчёты. Ранее подтверждённые педагоги сохраняют доступ, остальные получают профиль пользователя при миграции.

Заполняйте справочник в разделе «Организации». Педагог может выбрать организацию в профиле или в отчёте. При отсутствии записи в справочнике место проведения вводится текстом.

### Безопасный маршрут

Игра доступна по адресу `/safe-route/`. Район и условия собираются при старте из встроенных ситуаций для пешехода и велосипедиста. Гость может продолжить маршрут в том же браузере в течение двух часов. После входа он может перенести гостевой маршрут в свой кабинет. У аккаунта сохраняется один текущий или завершённый маршрут. После завершения можно скачать памятку со схемой пути.

Педагог может указать в отчёте уровень маршрута и количество завершивших. Без маршрута число завершивших остаётся пустым.

### Возрастные тесты

Миграция `0020_age_test_questions` загружает из `app/data/age_tests.json` по 30 вопросов для каждой из трёх групп. После первого запуска вопросы, варианты, правильные ответы и ссылки на пункты российских правил редактируются в разделе «Вопросы возрастных тестов» админки. Повторный запуск миграций сохраняет эти правки.

### Справочник знаков

После миграций и переноса старых данных добавьте стартовые карточки командой `python manage.py seed_road_signs`. Команда не перезаписывает существующие карточки. На Docker-стенде её можно выполнить через `docker compose -p znaipdd-dev --profile dev exec api-dev python manage.py seed_road_signs`.

### Практика и новости

Команда `python manage.py seed_practice` добавляет десять стартовых заданий, нужные знаки и вводную новость о практике. Запускайте её после миграций и переноса старых данных. Повторный запуск сохраняет редакторские правки.

В админке сначала создайте задание, затем сохраните его версию. В списке версий доступны предпросмотр, публикация, копирование в новый черновик и отзыв. В «Новостях и мероприятиях» сохраните черновик и опубликуйте его действием над выбранной записью.

### Занятия с классом

В кабинете подтверждённого педагога «Провести урок» открывает два занятия для общего экрана. «Мои тесты» содержит два готовых QR-теста и личную библиотеку. Сохраните готовую версию, запустите её и покажите классу QR или код со страницы запуска. Для ручного ввода ученики открывают `/join/`. Ссылка в QR использует адрес, по которому педагог открыл сайт. Для занятия с телефонов этот адрес должен быть доступен в сети школы.

Подключение открыто на 20 минут. Нажатие «Начать тест» запускает отдельный таймер на 20 минут. Закрытие входа сохраняет доступ уже подключившихся. Завершение фиксирует сводку. В истории запусков можно вернуться к занятию или его отчёту.

Срок личного разбора задаётся переменной `CLASSROOM_REVIEW_HOURS` (на тестовом стенде 24 часа). Перед работой с реальными классами оператор утверждает этот срок, а методист проверяет материалы. Сервис `classroom-cleanup` в Compose раз в минуту закрывает просроченные сессии и очищает ответы. Несданные черновики удаляются при закрытии. После окончания срока разбора удаляются сданные попытки и их привязка к браузеру. Сводка и отчёт остаются в кабинете. При запуске без Compose используйте `python manage.py cleanup_classroom --watch` либо периодически выполняйте `python manage.py cleanup_classroom`.
