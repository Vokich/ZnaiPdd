# Знай ПДД

Сайт использует React и TypeScript, серверную часть Django и REST API по адресу `/api/`. Веб-клиент, API и Django Admin работают на одном домене.

## Карта проекта

| Каталог | Что в нём находится |
| --- | --- |
| `backend/pdd_site/` | Настройки Django, подключения базы и кеша, входящие URL |
| `backend/app/` | Серверные разделы. В каждом рядом лежат его модели, обработчики, формы и редакторы. В `urls.py` собраны пути REST API, в `models.py` и `admin.py` Django регистрирует модели и редакторы |
| `backend/app/accounts/`, `backend/app/organizations/` | Регистрация, роли, контакты, справочник и привязка организаций |
| `backend/app/quizzes/`, `backend/app/signs/`, `backend/app/practice/`, `backend/app/routes/` | Возрастные тесты, знаки, практические задания и безопасные маршруты |
| `backend/app/classroom/`, `backend/app/news/` | Занятия по QR, отчёты педагогов и новости |
| `backend/app/rankings/`, `backend/app/reporting/`, `backend/app/documents/` | Начисление баллов, статистика, выгрузка Excel и PDF |
| `backend/app/data/`, `backend/app/migrations/`, `backend/app/management/commands/` | Исходные справочники, история схемы и команды обслуживания |
| `backend/app/security/`, `backend/app/editorial/` | Защита запросов, общие средства редактора публикаций и изображений |
| `backend/templates/admin/` | Шаблоны Django Admin. Серверные HTML-страницы прежнего интерфейса обслуживаются из `backend/app/legacy/` и `backend/app/templates/` |
| `frontend/src/app/`, `frontend/src/features/` | Маршрутизатор React и страницы каждого раздела |
| `frontend/src/shared/`, `frontend/src/styles/`, `frontend/public/` | Общие компоненты, клиент API, стили и публичная графика |

Команды Docker Compose выполняйте из корня репозитория. Здесь же находятся `Dockerfile`, `Caddyfile` и `.env.example`. Для прямого запуска Django перейдите в `backend/`. Зависимости устанавливаются командой `python -m pip install -c requirements/constraints.txt -r requirements/runtime.txt`.

## Локальный стенд

Запустите Docker Desktop и выполните из корня проекта.

```sh
docker compose -p znaipdd-dev --profile dev up --build -d
```

Сайт доступен на [localhost:5173](http://localhost:5173/), проверка API — на [localhost:5173/api/health/](http://localhost:5173/api/health/). Профиль `dev` запускает PostgreSQL и хранит базу и медиа в собственных томах Docker. При прямом запуске Django без `POSTGRES_HOST` используется отдельный локальный файл `backend/db.local.sqlite3`. Справочники знаков и организаций ведутся через [Django Admin](http://localhost:5173/admin/).

```sh
docker compose -p znaipdd-dev --profile dev exec api-dev python manage.py check
docker compose -p znaipdd-dev --profile dev exec api-dev python manage.py migrate --check
```

Если раньше вы запускали Django напрямую, укажите прежний файл SQLite через `DJANGO_DB_PATH` или перенесите его в `backend/` вместе с каталогом `media/`. В Docker путь к данным и имена томов сохраняются.

Для разработки с автоматической синхронизацией файлов используйте `docker compose -p znaipdd-dev --profile dev up --build --watch`.

## Первый администратор

Укажите `DJANGO_SUPERUSER_USERNAME` и `DJANGO_SUPERUSER_PASSWORD` в локальном `.env`. Оба профиля Docker создают активного суперпользователя Django после миграций, перед запуском сервера. При повторном запуске пароль существующего суперпользователя сохраняется. Если логин уже занят другой учётной записью, задайте свободный логин. Когда обе переменные пусты, создание пропускается.

## Профиль prod

Скопируйте `.env.example` в `.env` при первичной настройке. Укажите `DJANGO_SECRET_KEY`, `POSTGRES_PASSWORD`, домен в ASCII или Punycode и существующий каталог медиа. Django работает с UID и GID `10001` и использует этот каталог для загрузок. PostgreSQL доступен Django внутри сети Docker, его данные находятся в томе `postgres_data`. Домен должен указывать на сервер, а порты 80 и 443 должны быть доступны для Caddy.

```sh
docker compose --profile prod up --build -d
```

Django применяет миграции при старте. Caddy отдаёт сборку React, обслуживает TLS и направляет запросы `/api/` и `/admin/` в Django. Существующие тома Caddy сохраняют сертификаты при обновлении контейнеров.

### Доступ к отчётам и справочник организаций

В разделе «Пользователи» выберите профиль доступа: «Пользователь», «Педагог» или «Администратор». Назначайте «Педагог» после проверки учётной записи. Этот профиль открывает собственные отчёты. Ранее подтверждённые педагоги сохраняют доступ, остальные получают профиль пользователя при миграции.

Заполняйте справочник в разделе «Организации». Ученик или педагог пишет администратору в личные сообщения. В карточке пользователя администратор ищет организацию по названию, выбирает её и отмечает подтверждение. Для ранее самостоятельно выбранной организации тоже нужно подтверждение. В отчёте об уроке педагог может выбрать площадку из справочника или ввести место проведения текстом.

### Безопасный маршрут

Игра доступна по адресу `/safe-route/`. Район и условия собираются при старте из ситуаций, опубликованных в админке, для пешехода и велосипедиста. Гость может продолжить маршрут в том же браузере в течение двух часов. После входа он может перенести гостевой маршрут в свой кабинет. У аккаунта сохраняется один текущий или завершённый маршрут. После завершения можно скачать памятку со схемой пути.

Педагог может указать в отчёте уровень маршрута и количество завершивших. Без маршрута число завершивших остаётся пустым.

### Возрастные тесты

Миграция `0020_age_test_questions` загружает из `backend/app/data/age_tests.json` по 30 вопросов для каждой из трёх групп. После первого запуска вопросы, варианты, правильные ответы и ссылки на пункты российских правил редактируются в разделе «Вопросы возрастных тестов» админки. Повторный запуск миграций сохраняет эти правки.

### Справочник знаков

После миграций и переноса старых данных добавьте стартовые карточки командой `python manage.py seed_road_signs`. Команда не перезаписывает существующие карточки. На Docker-стенде её можно выполнить через `docker compose -p znaipdd-dev --profile dev exec api-dev python manage.py seed_road_signs`.

### Практика и новости

Команда `python manage.py seed_practice` добавляет десять стартовых заданий, нужные знаки и вводную новость о практике. Запускайте её после миграций и переноса старых данных. Повторный запуск сохраняет редакторские правки.

В админке сначала создайте задание, затем сохраните его версию. В списке версий доступны предпросмотр, публикация, копирование в новый черновик и отзыв. В «Новостях и мероприятиях» сохраните черновик и опубликуйте его действием над выбранной записью.

### Занятия с классом

В кабинете подтверждённого педагога «Провести урок» открывает два занятия для общего экрана. «Мои тесты» содержит два готовых QR-теста и личную библиотеку. Сохраните готовую версию, запустите её и покажите классу QR или код со страницы запуска. Для ручного ввода ученики открывают `/join/`. Ссылка в QR использует адрес, по которому педагог открыл сайт. Для занятия с телефонов этот адрес должен быть доступен в сети школы.

Подключение открыто на 20 минут. Нажатие «Начать тест» запускает отдельный таймер на 20 минут. Закрытие входа сохраняет доступ уже подключившихся. Завершение фиксирует сводку. В истории запусков можно вернуться к занятию или его отчёту.

Срок личного разбора задаётся переменной `CLASSROOM_REVIEW_HOURS` (на тестовом стенде 24 часа). Перед работой с реальными классами оператор утверждает этот срок, а методист проверяет материалы. Сервис `classroom-cleanup` в Compose раз в минуту закрывает просроченные сессии и очищает ответы. Несданные черновики удаляются при закрытии. После окончания срока разбора удаляются сданные попытки и их привязка к браузеру. Сводка и отчёт остаются в кабинете. Для готовых тестов платформы отдельно сохраняется административная статистика. У личных тестов педагога, включая копии, действует только разбор занятия. При запуске без Compose используйте `python manage.py cleanup_classroom --watch` либо периодически выполняйте `python manage.py cleanup_classroom`.

## Статистика и рейтинг

В Django Admin откройте «Статистика заданий платформы». Выберите период, раздел, организацию или найдите ученика по имени или логину. Откройте попытку для разбора. Кнопка «Скачать выборку в Excel» выгружает все страницы текущей выборки. Именные отчёты и Excel доступны суперпользователям.

Листы «Попытки», «Ответы» и «Сводка по вопросам» связаны номером попытки или названием задания и версией. Для маршрута каждое принятое действие в учебной ситуации, включая ошибку и повторный выбор, попадает в разбор. Для практики с табличками видны отдельные ответы. Попытки гостей и решения на общем экране отображаются без имени. Старые сохранённые итоги доступны с пометкой об отсутствии детализации.

Организация в статистике фиксируется в момент ответа. Рейтинг организаций суммирует баллы действующих участников личного зачёта с подтверждённой текущей организацией. Участие добровольное. За знак начисляется 1 балл, в тестах учитывается число верных ответов, за маршрут — результат после вычета ошибок (в общем зачёте минимум 0). В практике начальное задание приносит 3 балла, продвинутое — 5. Переиздания и повторные прохождения одного задания учитываются однократно по лучшему результату. У возрастных тестов свой лучший результат для каждой группы. Готовые QR-тесты платформы учитываются при прохождении из одного аккаунта от входа по коду до сдачи.

Параметр `PLATFORM_DETAIL_DAYS` задаёт срок хранения подробных ответов в административной статистике. Стартовое значение — 365 дней. Фоновая команда `cleanup_classroom` очищает эти ответы, сохраняя итоги. Срок личного разбора QR-занятия задаётся отдельно через `CLASSROOM_REVIEW_HOURS`.

## Контакты, маршруты и документы

В разделе «Контакты для педагогов» укажите ссылку для личных сообщений, когда она появится. Пустая ссылка зарезервирована на главной. Ссылки на сообщества редактируются там же.

«Ситуации маршрутов» содержат описания уровней, вопросы, действия, объяснения и ссылки на правила. Новую ситуацию можно добавить в группу «Пешком» или «На велосипеде». Изменения применяются к новым маршрутам. Начальное наполнение находится в `backend/app/data/route_scenes.json` и загружается миграцией один раз.

В «Результатах тестов» у успешно сданной попытки нажмите «Сформировать PDF». Ученик скачивает такой же документ из своего кабинета. От 60% выдаётся сертификат, от 80% — диплом. На обоих документах указан издатель — платформа «Знай ПДД».

## Лимиты на рабочем сервере

Профиль `prod` собирает Caddy с закреплённой версией модуля ограничения запросов. Caddy завершает TLS, обслуживает фронтенд, ограничивает размер тела API до 1 МБ и проксирует динамические запросы напрямую в Django. Redis хранит общие счётчики приложения. Наружу опубликованы только порты Caddy. Конфигурация рассчитана на прямое подключение к Caddy. При установке CDN укажите в Caddy `trusted_proxies` с сетями вашего провайдера и закройте прямой доступ к серверу в межсетевом экране провайдера.

| Переменная в .env | По умолчанию | Для чего |
|---|---:|---|
| EDGE_IP_PER_10S | 400 за 10 с | Динамические запросы с одного адреса, включая общий школьный IP |
| EDGE_TOTAL_PER_10S | 2000 за 10 с | Динамические запросы со всех адресов |
| RATE_LOGIN_IP / RATE_LOGIN_PAIR | 180 / 10 в минуту | Входы с адреса / с этого адреса в один аккаунт, включая админку |
| RATE_REGISTRATION | 150 за 10 минут | Регистрации с одного адреса |
| RATE_QR_MISSES | 18 за минуту | Неверные коды с одного адреса |
| RATE_WRITES_USER / RATE_WRITES_GUEST | 120 / 1200 в минуту | Изменения через API аккаунтом / гостями с одного IP |
| RATE_PDF / RATE_EXPORT | 12 / 3 в минуту | Скачивания PDF / выгрузки Excel на аккаунт |

1. Перед обновлением сохраните копию PostgreSQL и каталога медиа. Укажите нужные значения в серверном `.env`. Начать можно с таблицы выше.
2. Из корня проекта выполните следующие команды.

```sh
docker compose --profile prod config --quiet
docker compose --profile prod build web caddy
docker compose --profile prod run --rm --no-deps --entrypoint caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
docker compose --profile prod up --build -d
docker compose --profile prod ps
```

3. На тестовом домене временно установите `EDGE_IP_PER_10S=2`, пересоздайте Caddy командой `docker compose --profile prod up -d caddy` и трижды откройте `/api/health/` за 10 секунд. У третьего запроса проверьте HTTP 429 и заголовок `Retry-After`. После окна запрос снова должен вернуть 200. Верните значение 400 и пересоздайте Caddy. Для просмотра последних ответов используйте `docker compose --profile prod logs --since=10m caddy`.
4. Перед массовым уроком проверьте вход класса, сканирование QR, сохранение и сдачу ответов через одну сеть. Поднимайте только тот лимит, который сработал при обычной нагрузке. После правки переменных Django пересоздайте `web`. Для отката порогов верните прежние значения и повторите `docker compose --profile prod up -d`.
5. При атаке, заполнившей сетевой канал, включите фильтрацию трафика у хостера. Лимиты Caddy действуют после доставки запроса на сервер.

Подробности реализации приведены в [описании модуля Caddy](https://github.com/mholt/caddy-ratelimit) и [документации Caddy для request_body](https://caddyserver.com/docs/caddyfile/directives/request_body).
